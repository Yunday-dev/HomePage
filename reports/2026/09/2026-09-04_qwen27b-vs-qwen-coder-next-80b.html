같은 Unity 작업으로
두 로컬 모델을 비교했다

이전에 Qwen3.8-27B로 완료했던 Hero 이동·공격 기능 구현을 Qwen3-Coder-Next 80B에도 동일하게 맡겨 결과를 비교했다. 더 큰 코딩 특화 모델이 복잡한 코드베이스를 더 안정적으로 다룰 수 있을지 확인하는 것이 목적이었다. 결과적으로 Qwen3-Coder-Next 80B는 빠르게 코드를 작성했지만 컴파일과 테스트 검증 단계에서 신뢰성을 확보하지 못했다.

작업 목표

Qwen3.8-27B에서 이미 수행했던 기능을 그대로 다시 구현하게 해, Qwen3-Coder-Next 80B의 코드베이스 이해 능력과 실제 코딩 에이전트로서의 작업 완성도를 비교했다.

비교에서 확인하고 싶었던 것

  • 기존 Unity 전투 구조를 얼마나 정확하게 이해하는가
  • 여러 파일이 연결된 기능을 기존 구조를 활용해 구현하는가
  • 코드를 작성한 뒤 실제 컴파일까지 확인하는가
  • 관련 테스트와 전체 회귀 테스트를 직접 실행하는가
  • 오류가 발생했을 때 스스로 수정하고 다시 검증하는가

비교 방법

동일한 시작 코드와 동일한 작업 요청을 사용했다.

단순 응답 속도가 아니라 실제로 사용할 수 있는 코드까지 도달하는 시간을 중심으로 비교했다.

동일하게 수행한 작업

비교 대상은 Hero를 플레이어가 직접 조작할 수 있도록 이동과 공격 명령을 추가하는 기능이다. 전투, 이동, 입력, 카메라, UI가 함께 연결되기 때문에 단순 코드 생성보다 기존 프로젝트 구조 이해가 중요한 작업이다.

Hero 이동·공격 명령

  • Hero는 자동으로 적을 타겟으로 지정하거나 다른 적으로 자동 전환하지 않는다.
  • 적을 클릭하면 해당 적을 공격 대상으로 지정한다.
  • 빈 전장을 클릭하면 해당 월드 위치로 이동한다.
  • 지정한 적이 사라져도 다른 적을 자동으로 공격하지 않는다.
  • 일반 아군 유닛은 기존 자동 전투 동작을 유지한다.
  • UI 클릭은 이동·공격 명령으로 처리하지 않는다.
  • 기존 이동·공격·회피·분리 로직을 가능한 그대로 재사용한다.

완료 기준

구현 보고만으로 완료로 판단하지 않는다.

  • Unity 컴파일 성공
  • 관련 EditMode 테스트 통과
  • 전체 EditMode 테스트 통과
  • 최종 변경사항 검증
  • 필요한 경우 실제 Play Mode 확인

Qwen3.8-27B와 비교

두 모델은 같은 기능을 구현했지만 작업 과정의 성격은 크게 달랐다. Qwen3.8-27B는 시간이 오래 걸리고 Compaction이 발생했지만, 자동 테스트와 실제 Play Mode 검증을 거쳐 최종적으로 동작 가능한 상태에 도달했다. Qwen3-Coder-Next 80B는 더 빠르게 코드를 생성했지만 컴파일 검증 단계에서 작업이 끝나지 않았다.

이번 비교에서 확인한 점

1

모델 크기만으로 코딩 에이전트 성능을 판단하기 어렵다

80B 코딩 특화 모델은 코드 이해와 생성 속도에서 장점을 보였지만, 실제 프로젝트를 끝까지 완성하는 능력은 별도의 평가가 필요했다.

2

응답 시간보다 유효한 결과까지의 시간이 중요하다

빠르게 완료 보고를 반환해도 컴파일되지 않으면 실제 개발에서는 사용할 수 없다. 최종적으로 동작 가능한 상태까지 도달하는 시간을 기준으로 봐야 한다.

3

256K 컨텍스트의 여유는 분명했다

Qwen3-Coder-Next 80B는 이번 작업에서 Compaction 없이 세션을 유지했다. 긴 작업에서 컨텍스트 여유가 있다는 점은 분명한 장점이었다.

4

검증 과정도 모델 선택의 핵심 기준이다

코드 생성 능력뿐 아니라 실제 컴파일, 테스트 실행, 실패 원인 수정, 재검증을 스스로 반복하는지가 코딩 에이전트의 실사용성을 결정한다.

다음 작업
