작업 목표

기존에는 Hero도 일반 전투 유닛처럼 자동으로 적을 찾고 전투했다. 이번 작업에서는 Hero만 플레이어의 직접 명령을 받도록 변경하는 것을 목표로 했다.

플레이어가 직접 Hero를 지휘하도록 변경

  • 전장의 빈 공간을 클릭하면 Hero가 해당 위치로 이동한다.
  • 적을 클릭하면 해당 적을 공격 대상으로 지정한다.
  • 지정한 적이 사라져도 Hero가 임의로 다른 적을 찾아 공격하지 않는다.
  • 일반 아군 유닛은 기존 자동 전투 방식을 그대로 유지한다.
  • UI를 클릭했을 때는 전장 명령이 발생하지 않는다.

작업 범위

입력 처리부터 이동, 타깃 지정, 기존 전투 로직 연결, UI 클릭 구분까지 여러 시스템이 함께 연결되는 실제 게임 기능을 대상으로 했다.

기존 전투 시스템을 최대한 유지하면서 Hero 제어 방식만 분리하는 것이 중요했다.

작업 과정

로컬 코딩 AI 에이전트가 프로젝트 문서와 관련 코드를 분석한 뒤 구현과 테스트를 진행했다. 전체 과정에서 두 차례 사용자 판단이 필요했다.

1

기존 전투 구조와 테스트 영향 범위 분석

Analysis

Hero의 자동 전투를 제거할 경우 기존 전투 테스트 다수가 영향을 받을 가능성이 확인됐다. 로컬 코딩 AI 에이전트는 기존 테스트를 대규모로 수정할지, 실제 Hero만 수동 제어 대상으로 분리할지 판단을 요청했다.

사용자 개입 #1: 기존 자동 전투 동작은 유지하고, 실제 Hero만 수동 명령을 받도록 하는 방향을 선택했다.

2

조사 단계가 길어져 구현 진행 지시

User Intervention

선택된 방향을 기준으로 관련 호출 흐름과 전투 로직을 계속 조사했지만, 첫 작업 구간에서는 실제 코드 수정까지 이어지지 않고 종료됐다.

사용자 개입 #2: 충분한 정보가 확보됐다고 판단해 추가 조사를 멈추고 구현과 테스트를 진행하도록 요청했다.

첫 구간: 16분 32초 · Compaction 1회 / 1분 21초
3

Hero 이동·공격 기능 구현

Implementation

이후 로컬 코딩 AI 에이전트는 Hero의 자동 타깃 획득을 분리하고, 플레이어의 클릭에 따라 이동 또는 특정 적 공격 명령이 전달되도록 구현했다.

일반 아군 유닛의 자동 전투는 그대로 유지했고, Battle Camera 기준 좌표 변환과 UI 클릭 제외 처리까지 함께 연결했다.

자동 검증: Hero 관련 신규 테스트 12개 통과 · 전체 EditMode 테스트 272 / 272 통과 · git diff 검사 통과

구현 구간: 23분 10초 · Compaction 1회 / 2분 12초
4

자동 테스트 통과 후 실제 Play Mode 확인

Manual Verification

자동 테스트 결과만으로 작업을 종료하지 않고 Unity에서 실제 게임을 실행해 Hero를 직접 조작했다.

이 단계에서 프로젝트가 새로운 Input System을 사용 중인데 입력 코드 일부가 구형 입력 방식을 사용하고 있어, Play Mode 진입 직후 런타임 오류가 발생하는 것을 확인했다.

InvalidOperationException:
You are trying to read Input using the UnityEngine.Input class,
but you have switched active Input handling to Input System package.
5

실제 런타임 입력 환경에 맞게 수정

Runtime Fix

발견된 오류를 로컬 코딩 AI 에이전트에게 전달했고, 프로젝트 설정을 변경하는 대신 기존 Input System에 맞게 입력 처리 코드를 수정했다.

수정 범위는 입력 처리 코드로 제한했고, 전투 명령이나 UI 판정 등 이미 구현된 나머지 로직은 그대로 유지했다.

수정 후: Hero 관련 테스트 12 / 12 통과 · 전체 EditMode 272 / 272 통과 · 실제 Play Mode 정상 동작

런타임 수정 구간: 3분 38초 · Compaction 없음

실제 게임 실행

첫 Play Mode: 런타임 입력 오류

자동 테스트에서 실행되지 않았던 실제 입력 경로에서 프로젝트의 Input System 설정과 맞지 않는 코드가 발견됐다.

수정 후 Play Mode: 정상 동작

개발 기준: 입력·카메라·UI처럼 실제 Unity 실행 환경과 밀접한 기능은 자동 테스트 통과만으로 완료하지 않고, Play Mode에서 실제 조작까지 확인해야 한다.

로컬 코딩 AI 에이전트 작업에서 관찰한 점

이번 작업에서는 최종 코드뿐 아니라 기능을 완성하는 과정에서 어떤 부분에 사용자 판단이 필요했는지도 확인할 수 있었다.

기존 시스템을 유지하며 기능을 확장

Hero만 수동 제어 대상으로 분리하면서 일반 아군 유닛의 기존 자동 전투는 그대로 유지했다. 큰 구조를 새로 만들기보다 현재 시스템을 읽고 필요한 부분만 확장하는 방식으로 작업했다.

큰 변경 전에 사용자 판단 요청

기존 테스트 다수가 영향을 받을 가능성을 발견했을 때 임의로 대규모 수정을 진행하지 않고 방향을 질문했다. 작업 안정성 측면에서는 유용한 행동이었다.

조사 단계의 종료 판단은 보완 필요

첫 작업 구간에서는 충분한 구조를 파악한 뒤에도 구현으로 넘어가지 않고 조사를 이어가다가 종료됐다. 사용자가 구현 진행을 명시한 뒤에는 실제 수정과 테스트가 빠르게 진행됐다.

명확한 런타임 오류에는 빠르게 대응

실제 Play Mode에서 발생한 입력 오류를 전달한 뒤에는 3분 38초 만에 원인을 좁혀 입력 처리만 최소한으로 수정하고 전체 테스트까지 다시 마쳤다.
