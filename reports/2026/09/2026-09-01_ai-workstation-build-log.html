AI Workstation

RTX 5090으로 로컬 AI Workstation 구축하기

RTX 5090의 GPU 자원을 AI 추론에 집중시키고 실제 Unity 개발은 맥북에서 수행하는 개인용 로컬 AI 개발 인프라를 만든다. 이 문서는 왜 이 구조를 만들기 시작했는지부터, 무엇을 어떻게 구축했고 어떤 결과를 얻었는지, 다음에 무엇을 검증할지까지 하나의 Work Log로 정리한다.

Server: Windows + RTX 5090 32GB Client: MacBook Pro Runtime: llama.cpp / llama-server Model: Qwen3.8-27B Q4_K_M API: OpenAI-compatible Agent: OpenCode
작업 배경현재 상태구축 타임라인아키텍처다음 작업최종 운영 목표

이 작업은 무엇인가

RTX 5090 PC를 단순한 고성능 데스크톱이 아니라, Unity 개발 환경 뒤에서 상시 추론을 제공하는 개인용 AI Compute Server로 전환하는 작업이다.

하고자 하는 일

Windows PC의 RTX 5090은 가능한 한 큰 로컬 LLM을 로딩하고 llama-server로 API를 제공한다. MacBook Pro에서는 Unity, Rider, Git, OpenCode와 프로젝트 파일을 유지하며 실제 개발을 진행한다.

핵심 구조: MacBook은 개발과 Agent 실행을 담당하고, Windows 5090은 추론 계산만 담당한다.

왜 시작했나

  • GPU 자원 집중: Unity·브라우저·개발 도구가 5090의 VRAM과 시스템 자원을 함께 쓰지 않도록 역할을 분리한다.
  • 더 큰 로컬 모델: 32GB VRAM을 최대한 모델과 KV cache에 배정하고, 필요하면 시스템 RAM offload까지 활용한다.
  • 실제 코딩 Agent 검증: 로컬 모델이 단순 채팅을 넘어 Unity 저장소를 읽고, 수정하고, 테스트하는 개발 에이전트로 쓸 수 있는지 확인한다.
  • 개발 워크플로 선택지 확보: 반복적인 로컬 작업은 5090 모델이 맡고, 더 어려운 작업은 클라우드 코딩 모델과 역할을 나눌 수 있는 기반을 만든다.

검증하려는 가설

01 · 성능

RTX 5090 한 장으로 실사용 가능한 코딩 모델을 충분히 빠르게 서빙할 수 있는가?

02 · 분리

Unity 프로젝트와 개발 도구는 Mac에 둔 채, LAN API만으로 원격 GPU 추론을 자연스럽게 사용할 수 있는가?

03 · Agent

OpenCode + 로컬 Qwen이 Read/Glob에서 끝나지 않고 Edit/Shell/Test까지 안정적으로 수행할 수 있는가?

구축 타임라인

“무엇을 / 어떻게 / 왜” 순서로 기록한다.

1

런타임 선택

Decision

무엇을: LM Studio, Ollama, llama.cpp를 비교하고 메인 런타임을 llama.cpp로 결정.

왜: 5090을 전용 추론 서버로 쓰고, 80B 이상 모델에서 GPU layer·KV cache·CPU offload를 직접 제어하기 위해.

llama.cpp
└─ llama-server
   └─ CUDA
      └─ RTX 5090
2

초기 GPU 환경 확인

어떻게: nvidia-smi로 RTX 5090 32GB, Driver 591.86, CUDA 13.1 확인.

왜: 드라이버/CUDA/backend 문제를 모델 문제와 분리하기 위한 기준점 확보.

3

winget llama.cpp 설치 → Vulkan 확인

무엇을: winget install llama.cpp 실행.

결과: llama-b10711-bin-win-vulkan-x64.zip이 설치되고 RTX 5090이 Vulkan0으로 인식됨.

판단: 실행은 가능하지만 NVIDIA 전용 추론 서버 목표에는 CUDA가 더 적합.

4

NVIDIA 드라이버 업데이트

결과: NVIDIA-SMI 616.56 / CUDA UMD 13.4.

왜: 초기 591.86에서 보고된 RTX 5090 + llama.cpp CUDA 이슈 가능성을 제거하고 최신 CUDA 13.x 실행 환경으로 정리.

5

Vulkan llama.cpp 제거

winget uninstall --id ggml.llamacpp

왜: PATH에서 Vulkan 실행 파일과 CUDA 실행 파일이 충돌하는 것을 방지.

6

AI 디렉터리 구조 결정

결정: SSD인 C:에 실제 실행 모델과 런타임 배치. HDD D:/E:는 cold storage 용도.

C:\AI\
├─ llama.cpp\
├─ models\
├─ config\
├─ logs\
└─ benchmarks\

왜: GGUF 로딩과 mmap은 SSD가 훨씬 유리.

7

CUDA llama.cpp 직접 설치

Windows x64 CUDA 13.3 빌드와 CUDA runtime DLL을 C:\AI\llama.cpp에 설치.

.\llama-cli.exe --list-devices
CUDA0: NVIDIA GeForce RTX 5090

결과: CUDA backend 정상 인식.

8

첫 모델 선정 — Qwen3.8-27B Q4_K_M

왜: 약 19GB로 5090 VRAM에 완전히 들어가고, KV cache/context 여유를 남기며 코딩 Agent baseline으로 쓰기 좋기 때문.

.\llama-cli.exe -hf ggml-org/Qwen3.8-27B-GGUF:Q4_K_M \
  --no-mmproj -ngl all -c 32768 -fa on --perf
9

27B 성능 검증

GPU 온도 약 55°C, 전력 약 268W. Windows에서 보인 약 18GB working set은 대부분 공유 가능 mmap/file-backed 영역이며 private memory는 약 469MB.

10

CLI → llama-server 전환

왜: MacBook의 OpenCode가 HTTP API로 5090 모델을 호출하기 위해.

.\llama-server.exe `
  -hf ggml-org/Qwen3.8-27B-GGUF:Q4_K_M `
  --no-mmproj -ngl all -c 32768 -np 1 -fa on `
  --alias qwen3.8-27b --host 0.0.0.0 --port <PORT> `
  --api-key $apiKey

Windows 로컬 API 검증

# {"status":"ok"}

/v1/models에서도 qwen3.8-27b를 확인.

12

네트워크 프로필 및 고정 IP

MacBook과 같은 신뢰 LAN에서 사용하기 위해 Windows 네트워크를 Private으로 사용하고 서버의 사설 LAN IP를 고정.

13

MacBook → Windows 연결 확인

curl http://<AI-SERVER-LAN-IP>:<PORT>/health
# {"status":"ok"}

결과: MacBook과 5090 AI 서버 간 LAN 연결 성공.

14

MacBook OpenCode 설치

최초 ~/.local/state/opencode 권한 오류를 ~/.local 소유권 정상화로 해결.

sudo chown -R "$USER":"$(id -gn)" ~/.local
15

OpenCode custom provider 연결

초기 v2 schema(providers/package/settings)가 현재 설치본과 맞지 않아 stable schema(provider/npm/options)로 수정.

{
  "model": "local5090/qwen3.8-27b",
  "provider": {
    "local5090": {
      "npm": "@ai-sdk/openai-compatible",
      "options": { "baseURL": "http://<AI-SERVER-LAN-IP>:<PORT>/v1" }
    }
  }
}

OpenCode 하단에 Qwen3.8 27B @ RTX 5090 표시 확인.

16

API Key 전달 문제 해결

OpenCode에서 일시적으로 Invalid API Key 발생. Mac curl은 정상이라 서버/키/네트워크가 아니라 OpenCode credential 전달 범위 문제로 좁힘. 이후 정상 연결 완료.

17

첫 실제 Coding Agent 테스트

읽기 전용으로 Unity 프로젝트 구조 분석을 요청.

Examine this Unity project. Do not modify any files.
Identify the main gameplay architecture and list the five most important C# scripts...

OpenCode/Qwen이 실제로 Glob, Read를 수행하고 GameManager, CombatDirector, Combatant, UnitProductionController, ResourceController 등을 분석.

의미: 단순 채팅이 아니라 실제 repository tool loop 동작 확인.

18

현재 병목 발견 — Context / Compaction

여러 C# 파일을 읽는 과정에서 OpenCode Compaction이 발생. 32K context는 작은 분석에는 충분하지만 장기 코딩 Agent 작업에는 빠듯할 가능성이 있음.

다음 검증: 32K baseline을 남긴 뒤 64K context에서 동일 작업을 비교.

현재 아키텍처

┌────────────────────────────────────┐ │ MacBook Pro │ │ │ │ Unity / Rider / Git │ │ OpenCode │ │ Unity Project │ │ │ │ Read / Edit / Shell / Build / Test │ └──────────────────┬─────────────────┘ │ │ HTTP / LAN │ OpenAI-compatible API ▼ ┌────────────────────────────────────┐ │ Windows RTX 5090 AI Workstation │ │ │ │ llama-server :<PORT> │ │ Qwen3.8-27B Q4_K_M │ │ CUDA │ │ RTX 5090 32GB │ └────────────────────────────────────┘

역할 분리 원칙

  • MacBook: 프로젝트 파일과 개발 도구를 소유
  • Windows: 추론만 수행
  • Unity 프로젝트를 Windows SMB에 두지 않음
  • 모델 weight는 Windows SSD/VRAM에 유지
  • Agent가 필요한 코드만 HTTP 요청 context로 전달

지금부터 해야 할 일

목표는 “모델이 답한다”가 아니라 “실제 Unity 작업을 안정적으로 끝낸다”로 바뀐다.

1

32K 실제 코드 수정 테스트

Read/Glob만 검증했으므로 Create/Edit/Shell/Git diff/Error recovery를 확인한다.

Add a simple PlayerMover.cs component...
After implementation, inspect the diff and verify Unity compilation issues.
2

32K baseline 기록

총 작업 시간, tool call 수, compaction 횟수, prompt/generation tok/s, VRAM/RAM, 전력, 온도를 기록한다.

3

64K Context 테스트

-c 65536으로 변경하고 OpenCode context limit도 65536으로 맞춰 같은 작업을 반복한다. Compaction 감소와 VRAM 증가를 비교한다.

4

OpenCode 인증 영구화

새 shell마다 export하지 않아도 opencode 실행 즉시 local5090이 연결되도록 credential 저장 방식을 고정한다.

5

llama-server 자동 실행

Windows 부팅 → 모델 로딩 → API 준비까지 자동화. 초기에는 Task Scheduler가 가장 단순하다.

6

서버 profile 스크립트

start-fast.ps1, start-deep.ps1, start-lab.ps1 형태로 모델·context·로그 설정을 분리.

7

Qwen3-Coder-Next 80B 테스트

RTX 5090 32GB + System RAM 64GB를 사용한 GPU/RAM offload. 27B보다 실제 개발 생산성이 좋아지는지 측정한다.

8

27B vs 80B vs Codex A/B 테스트

동일 Unity task로 속도, tool 정확도, compile/test 성공률, 과잉 수정 여부를 비교한다.

9

Unity Test Runner 연결

Agent가 수정 → EditMode test → 로그 분석 → 재수정 → 재테스트까지 수행하게 만든다.

10

Repo 규칙 문서 정비

AGENTS.md, ARCHITECTURE.md, PROGRESS.md, TESTING.md로 긴 context보다 정확한 프로젝트 지침을 제공한다.

11

5090 VRAM 추가 확보

80B/긴 context 단계에서 Windows 화면 출력을 iGPU로 넘겨 RTX 5090을 compute 전용으로 만드는 것을 검토.

12

RAM 128GB 업그레이드 판단

80B 테스트 결과를 보고 결정. 27B GPU resident에는 불필요하지만 80B/125B/MoE offload에서는 가치가 커진다.

13

AI 모델 전용 NVMe SSD 검토

현재 C: SSD로 충분. 여러 quant/model을 장기 보유하기 시작하면 2TB NVMe를 AI 모델 전용으로 분리한다.
